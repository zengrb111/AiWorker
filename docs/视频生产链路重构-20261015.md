## 一、这次改了什么

把四条视频链路从「**OpenClaw agent 每次自由编写 Remotion 代码再渲染**」改造为「**DSH 只产出结构化分镜 JSON + 项目内置 Remotion 工程确定性渲染**」。

四条链路：

| 链路 | 入口 |
| --- | --- |
| 一键生成视频 | `gen-video/route.ts` |
| 一键剪视频 | `montage/route.ts` |
| 一键复刻爆款 | `remake/route.ts` |
| 后台批量出片 | `content-ingest.ts` |

改造前，Remotion 工程整体寄生在被 gitignore 的第三方目录里（`OpenMontage/remotion-composer`），分镜无结构化契约，AI 每次自由发挥导致质量不可复现，渲染慢且失败难定位。

---

## 二、解决的核心问题

### 1. 结尾口播被掐断（用户报告）

**现象**：口播没结束，视频已经停了。

**根因**：成片时长有**两个独立来源**——一边是 AI 估出来的分镜长度（`sceneDurationSeconds` 求和），另一边是 TTS 合成的真实配音时长。两者对不上时只能事后弥合：短了用 `tpad=clone` 冻结末帧补，长了尾部没人填充直接黑屏。

**修复**：契约改为**绝对时间轴**。

```
旧：sceneDurationSeconds（相对时长）→ 求和 → 与配音时长比对 → 事后 pad/trim
新：TTS 句级时间戳 → TimelineBeat 骨架 → AI 只挂画面/文字 → 出点必然落在某句结束处
```

成片长度 = 最后一个画面出点 + 片尾，**由构造等于口播长度**，不再依赖事后弥合。

关键文件：
- `remotion/src/vertical/schema.ts` —— `outSeconds`（必填）、`TimelineBeat`、`OverlaySpec`
- `remotion/src/vertical/layout.ts` —— `totalFrames` 纯由排版推导
- `src/lib/video/storyboard.ts` —— prompt 以时间轴为骨架，兜底分镜同样建在时间轴上
- `src/lib/video/pipeline.ts` —— 成片时长硬断言（短于口播 0.5s 立即告警）

### 2. 视频只有前几秒有画面，之后全黑

**根因**：`VerticalStoryboard` 的 `<Sequence>` 漏了 `from`，Remotion 默认 `from=0`，所有场景叠在第 0 帧。

**附带修复**：`resolveTotalFrames` 原先取 `max(排版长度, 模型声明时长)`，方向写反了——声明值偏大时多出的差值无人填充，反而制造黑屏。已改为纯排版值。

### 3. 动画效果不多、缺少设计感

**运镜幅度过小**：位移只有 `±3.5%~4.5%`（38~86px），分摊到 3 秒 90 帧里每帧不到 1 像素，肉眼等于静止。已拉到短视频该有的量级（缩放 20%+、位移 ±8%）。

**prompt 在劝阻 AI 用 overlays**：原 prompt 写「可选」「最多 4 个」「不需要每句都压字」，三重限制下 AI 基本不用。已改为明确编排要求：覆盖时间轴 60%~80%、运镜必须交替、粒子不要全程开、相邻场景光影色温要拉开。

**兜底分镜只有一个标题**：DSH 不可用时退化成「纯图片轮播 + 一个标题」。已重写为铺满时间轴（开场 hero_title + 每 2 句段落标题 + 结论 callout + progress 条）。

## 三、新增能力

### 1. 项目内 Remotion 工程

`remotion/` 目录，3 个竖版合成（1080×1920@30fps）：

| 合成 | 用途 |
| --- | --- |
| `VerticalStoryboard` | 图片 → 视频 |
| `VerticalMontage` | 视频片段剪辑 |
| `VerticalRemake` | 爆款复刻 |

- 14 个文字/图表组件 + `AnimatedBackground` 动态背景（漂移渐变 + 光球 + 呼吸网格线）
- `OverlayLayer` 适配层：AI 只声明「这句压一张 92% 数据卡」，具体字号/配色/弹簧由主题决定
- 字体走系统字体栈，**刻意不放字体文件进仓库**（`.ttc` 在 Web Font 下不保证可解析，转 woff2 体积巨大）
- 渲染复用本机 Chrome（`REMOTION_BROWSER_EXECUTABLE`），避免数百 MB 下载

### 2. 主题库 4 → 9 套

给 `ThemeConfig` 新增 `effects: VisualEffect[]` 字段——**没有它，新风格只能换配色**。故障风换配色换不出 RGB 错位，拼贴风也换不出撕纸边。

| 风格 | effects | 新增组件 |
| --- | --- | --- |
| 酸性设计 | `acid-flow` | `AcidFlowLayer`（三层流体团 + 斜向金属高光） |
| 故障艺术 | `glitch` | `GlitchLayer`（RGB 错位 + 偶发撕裂 + 扫描线） |
| 拼贴胶带 | `collage` | `CollageFrame` + `TornPaperBorder`（SVG evenodd 镂空撕纸边） |
| 瑞士网格 | `swiss-grid` | `SwissGridLayer` |
| 单色水墨 | — | 纯配色 |

每套单独调 `springConfig`：酸性低阻尼（弹）、瑞士高阻尼（干脆）、故障阻尼最低（像被信号打断）。

### 3. 素材识图

`src/lib/vision.ts` —— 批量识图，输出内容/情绪/主体/色调。

- **语义匹配**：图文按内容对口，「图片编号不再是播放顺序」
- **自动选主题**：`src/lib/video/style.ts`，按「明度优先 → 色相定调 → 饱和度」推断。亮图只能用亮主题（这条最不能违背，亮图配深主题会让字幕和图糊成一片）
- **降级**：识图失败 → insights 为空 → prompt 自动退回纯路径列表，行为与改造前完全一致

前端「一键生成视频」面板新增**视频风格**下拉框（自动 + 9 套）。

### 4. 可观测性与回退

- `VIDEO_RENDER_ENGINE=dsh|openclaw` 开关，旧路径保留可秒级回退
- OpenClaw 诊断层：`classifyGatewayError` 七类故障分类 + `GET /api/openclaw/health` + `scripts/diagnose-openclaw.mts`
- 画面黑屏自检：ffmpeg `blackdetect` 全片扫描，纳入每次出片
- SSE 心跳保活（长任务不断流）

## 四、修复的既有缺陷

| 缺陷 | 影响 |
| --- | --- |
| `ws.on("error")` 只取 `error.message`，Node 部分错误形态下不填 → 界面显示「连接失败：」空串 | 更严重的是 `isGatewayTransientError` 只匹配 message 文本，空 message 被判非瞬时，**跳过 150 秒重试** |
| `ClipFilmstrip` 转场归属错位 | 转场整体后移一位（clip0→clip1 永远硬切），且末 clip 转场帧无 Transition 消费，**每条 montage/remake 成片固定多出 0.5 秒** |
| `classifyGatewayError` 的 `auth_failed` 正则过宽 | `reject`/`token`/`scope`/`device` 会误伤普通消息，让用户白去「重新注册设备」；且排在 timeout 之前导致超时被吞 |
| `readMarkedDiagnosis` 降级解析恒不匹配 | 正则要求半角 `(kind)`，实际 message 结尾是全角 `）`，属性丢失时 kind 永远退化成 `unknown` |
| `vision.js` env 解析不一致 | 自研解析「先到先得」vs dotenv「后者覆盖」，同一文件两套结果，脚本直接退出 |
| `start-all.cmd` 全中文 + 旧机器路径 | cmd 按 GBK 解析 UTF-8 文件，中文乱码**被当命令执行**；三条路径指向已退役机器，双击静默失败 |
| DSH session id 未清洗字符 | `prepare-${topic}` 把中文热点名拼进 session id，DSH 只接受 ASCII，降级路径必然失败 |
| `resolveTotalFrames` 取 `max` | 方向写反，模型声明值偏大时制造尾部黑屏 |

## 五、架构

```
UI (platform-client.tsx)
   │
API 路由（鉴权 / 表单解析 / SSE / 落库）
   │
src/lib/video/pipeline.ts  ← 唯一编排入口，四条链路共用
   │
   ├→ storyboard.ts ─→ dsh.ts ─→ scripts/dsh-storyboard/main.py（DeepSeek）
   │      ↑ 三级兜底：解析失败 → 回喂错误重试 → 确定性兜底分镜
   │
   ├→ vision.ts（识图）─→ style.ts（自动选主题）
   │
   ├→ render.ts（并发闸门 + props 落盘）─→ remotion/ 三个竖版合成
   │
   └→ video-stitch.ts（后期：混音 / 字幕 / 片头 / 封面，一行未改）
```

分镜数据流（关键契约）：

```
参考图 ──┐
创作要求 ─┼→ buildStoryboardPrompt() → DSH → Storyboard JSON
口播时间轴┘         ↓
                  校验（schema.ts）
                   ├ 通过 → props.json
                   ├ 失败 → 回喂错误重试一次
                   └ 仍失败 → 确定性兜底分镜
                                    ↓
                        npx remotion render --props=<abs>
```

## 八、已知限制与后续

1. **酸性风格渲染偏慢**：实测 129.4s（原约 60s），因叠加 3 层 `blur(46px)` 流体，无头 Chromium 软件渲染吃 CPU。可降 blur 半径或减流体层数。
2. **montage / remake 的风格选择 UI 未加**：后端已支持 `theme` 透传，前端面板待补。
3. **`start-all.cmd` 的 `NODE_DIR` 写死本机路径**：脚本已做 fallback（找不到会退到 PATH 里的 node），不影响他人使用。
4. **Linux 服务器渲染需额外处理字体**：当前依赖 Windows 系统字体（微软雅黑优先）。
5. **`.mts` 脚本不在 `tsc` 覆盖范围**：`tsconfig.json` 的 include 只匹配 `**/*.ts` / `**/*.tsx`，`scripts/*.mts` 四个文件的类型错误无人把关。
6. **横版 composition 未注册**：`Root.tsx` 目前只注册 3 个竖版合成，本地版原有的 13 个横版 composition 未迁入。
