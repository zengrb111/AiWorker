# 用户级模型配置改造（2026-10-16）

把平台所有模型 token 的归属从「全局公共」改为「按登录用户隔离」，并在「系统配置」菜单下把模型配置做成真实可用的功能。

## 一、目标与结果

| 目标 | 结果 |
| --- | --- |
| token 归属到具体用户 | `UserModelProvider`（服务 + 加密密钥）与 `UserModelAssignment`（能力分配）全部以 `userId` 为维度存储 |
| 用户之间互不可见 | 所有查询强制带 `userId`；删除/测试/分配均按 `id + userId` 定位 |
| 「系统配置 → 模型配置」真实可用 | 新增 `settings-panel.tsx`（增删改 + 测试连接 + 8 项能力分配 + 空状态引导） |
| 不依赖公共密钥 | 对话、热点、识图、OCR、配音、文生视频、分镜规划全部走用户自己配置的模型与密钥 |
| 未配置即不可用 | 抛 `ModelConfigError`，文案明确指向「系统配置」，不存在平台兜底 |

## 二、数据模型

### UserModelProvider（一个模型服务一行）

| 字段 | 说明 |
| --- | --- |
| `userId` | 归属用户（`onDelete: Cascade`） |
| `providerId` | 预置标识（zhipu/qwen/doubao/hunyuan/deepseek/tavily/bocha…）或自定义 |
| `label` | 展示名；用于区分「同一供应商配多份 key」 |
| `apiFormat` | `openai-completions` / `zhipu-tts` / `dashscope-tts` / `pollinations-video` / `tavily-search` / `bocha-search` |
| `baseUrl` | 上游接口地址 |
| `credentialEnc` | AES-256-GCM 加密的 JSON blob：`{"apiKey":"...","apiSecret":"..."}`（博查需双密钥） |
| `modelsJson` | `[{"id":"glm-4.6","name":"GLM-4.6"}]` |
| `status` / `statusMsg` / `lastVerifyAt` | `untested` / `ok` / `invalid` + 具体原因 |

唯一约束 `@@unique([userId, providerId, apiFormat, label])`：同一用户同一供应商可配多份（label 区分），不同用户配同一 provider 互不干扰。

### UserModelAssignment（一项能力一行）

`@@unique([userId, capability])`，`providerRowId` 指向 `UserModelProvider.id`（行级引用，消除歧义）。

`capability` 枚举：`chat`（对话与写作）/ `vision`（识图）/ `ocr`（图片文字识别）/ `tts`（配音）/ `video`（文生视频）/ `storyboard`（分镜规划）/ `embedding`（向量化）/ `search`（联网搜索）。

> 用枚举列而非多列：新增能力只需插数据，不改 schema。

| `src/lib/image-search.ts` | 新闻配图检索（零 key）：百度图片搜索 acjson 端点，取 `middleURL` 直链 + `fromURLHost` 来源站；按 url 去重、单站点最多 2 张、多关键词交错 |
| `src/lib/model-presets.ts` | 预置供应商（含 TTS / 搜索 / 视频形态），前端表单自动填 baseUrl 与常用模型 |

### 为什么需要内置公开热榜

改造前「今日全网热点」**不使用任何搜索 API**：Gateway 的 `hot-topic-digest` skill 里写着 `web_search is normally unavailable here`，所以它直接抓公开热榜页面（tophub / 60s / 百度）。如果迁移后只留 Tavily、博查这两种需要付费 key 的搜索服务，等于把「开箱即用的当日热点」降级成「先注册付费服务」，属于能力倒退。

公开热榜不需要任何密钥，因此不涉及密钥隔离问题：**用户配了自己的搜索服务就优先用自己的，没配就用内置的**。注意用户服务失败时**不会**偷偷回落到内置榜 —— 否则用户会以为拿到的是他付费搜出来的结果。

实测（2026-10 本机）：稳定拿到 12~20 条真实当日热点，耗时 3~4.7s。百度最快，60s 系列偶发 10s 级慢响应，所以策略是「拿到 2 个源即收工，只有 1 个源则等满 3.5s 放行，全部失败才补 weibo」。

### 配图为什么不能由模型直接给 URL

热榜给的是**榜单页/搜索页链接**（`baidu.com/s?wd=…`、`toutiao.com/trending/…`），不是图片。若让模型从素材里"挑 URL 当配图"，下载必然全部失败 —— 这就是最初「未能取回关联配图」的根因。

改造前 agent 靠第二个 skill（`web-link-sourcing` → `image-links.md`）用百度图片搜索 JSON 端点拿真实直链。应用内复刻了这条路径，并把职责切开：

1. 模型只产出 `imageKeywords`（3~6 个具体名词短语，不给链接）
2. `image-search.ts` 用检索词去百度图片端点换直链（零 key）
3. `prepare` 下载并按 content-type 校验，带来源 Referer 降低防盗链拦截

实测：26 张候选、12 张下载全部成功（200 image/jpeg、23~367KB），来源覆盖新浪、搜狐、中国日报、光明网等。注意 `fromURLHost` 可能是「全网资源」这类中文站名，不能直接拼进 Referer（HTTP 头必须是 ASCII），`refererFor` 已做校验。

## 四、API 契约

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/settings/models` | 列出当前用户的 provider（含掩码 key、状态、被哪些能力引用）+ 8 项能力当前分配 |
| `POST /api/settings/models` | 新增/更新服务。body：`{id?, providerId, label, apiFormat, baseUrl, apiKey?, apiSecret?, models[]}`。`apiKey` 留空且已存在 = 不修改；改动后状态回落 `untested` |
| `POST /api/settings/models/test` | body `{providerRowId}`，用该服务自己的凭据探测，写回 `status/statusMsg/lastVerifyAt` |
| `DELETE /api/settings/models/[providerId]` | 按 `id + userId` 删除；同事务清理引用它的能力分配 |
| `PUT /api/settings/assignments` | body `{assignments:[{capability, providerRowId, model}]}`；`null` 表示清空。校验 provider 归属本用户且 model 在其列表内 |
| `GET /api/models` | 当前用户的模型清单 + `chat` 当前分配（供模型选择器） |
| `POST /api/models/switch` | body `{model, providerRowId}` → upsert `chat` 分配 |
| `POST /api/models/provider` | 兼容入口：等价于 `POST /api/settings/models`（对话接口形态） |

### 错误分类

- `ModelConfigError`：`no_provider`（还没添加服务）/ `no_assignment`（没指定默认模型）/ `invalid_key`（密钥缺失或解密失败）
- `UpstreamModelError`：`invalid_key` / `not_found`（接口地址或模型 id 不对）/ `rate_limited` / `bad_request` / `timeout` / `server` / `network`
- `SearchError`：`invalid_key` / `rate_limited` / `timeout` / `server` / `no_result` / `unsupported`

## 十、上线后实测暴露的两个降级问题（已修）

真实跑一次「一键生成视频」，界面连报两条降级。两条都不是模型能力问题，而是接线漏了「归属用户」。

### 1. 配音与分镜同时降级 —— 三个路由漏传 `userId`

现象：

```
所选引擎不可用，已自动切换到本机语音合成配音（约 76.0 秒）
原因：cloud:未在系统配置中指定云端配音模型 | edge:edge-tts failed (exit 1)
未配置 DeepSeek，改用默认分镜节奏…
```

根因：`synthesizeNarration` 与 `getDshStatus` 都靠 `userId` 去 `resolveCapabilityConfig` 取该用户的「配音 / 分镜」配置。而 `runVideoPipeline` 的三个调用方都没传：

| 文件 | 状态 |
| --- | --- |
| `src/app/api/conversations/[id]/gen-video/route.ts` | 已补 `userId: user.id` |
| `src/app/api/conversations/[id]/remake/route.ts` | 已补 `userId: user.id` |
| `src/app/api/conversations/[id]/montage/route.ts` | 已补 `userId: user.id` |
| `src/lib/gen-video.ts`（脚本） | 本来就传了，所以只有界面入口复现 |

三条视频入口全中，唯独脚本路径正常 —— 这就是典型的「类型上允许漏传」。

**防复发**：把 `VideoPipelineInput.userId` 由可选改为**必填**，漏传直接编译不过，而不是运行时静默降级。

### 2. edge-tts 握手 403 —— 两个 Python 装的是不同版本

上一步补完 `userId` 后 cloud 通道正常了，但 edge 兜底仍 `exit 1`。原始报错毫无信息量：

```
aiohttp.client_exceptions.WSServerHandshakeError: 403, message='Invalid response status',
url='wss://speech.platform.bing.com/...&Sec-MS-GEC=...&Sec-MS-GEC-Version=1-143.0.3650.75'
```

真实原因：edge-tts 7.2.x 的 `Sec-MS-GEC` 令牌算法已被微软废弃，握手一律 403，**与本地环境无关**。

**第二个坑**：本机有两套 Python，`resolvePythonPath()` 选的是托管那套：

| 解释器 | 版本 | edge-tts | 说明 |
| --- | --- | --- | --- |
| `~/.workbuddy/binaries/python/envs/default/Scripts/python.exe` | 3.13 | 7.2.8 → **7.3.1** | 项目实际使用（`resolvePythonPath()` 优先命中） |
| PATH 上的 `python` | 3.12 | 7.2.8 → **7.3.1** | 我第一次 `pip install -U` 装的是这个，**白装** |

于是出现「明明升级过了还是 403」的假象。修复命令必须用项目实际选中的解释器：

```powershell
& "$env:USERPROFILE\.workbuddy\binaries\python\envs\default\Scripts\python.exe" -m pip install -U edge-tts
```

代码侧加固（`src/lib/tts.ts`）：

- `explainEdgeFailure()` 把 403 / 缺模块翻译成人能照做的提示，**并强制打印本次使用的解释器路径**与配套升级命令
- 原先没有超时，edge-tts 挂死时会白等 76 秒才降级；现改为双保险：Python 侧 `asyncio.wait_for` + TS 侧 `child.kill()` 定时器，超时按文本长度放宽（45s + 120ms/字）
- `child.on("close"/"error")` 增加 `settled` 幂等标记，避免超时与 close 同时触发导致重复 reject

升级后实测：`generateTTS` 1.9 秒返回，8.61 秒音频，句级字幕正常。
